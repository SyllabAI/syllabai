- Finding (session 24, deployment): three production-only failure classes that local/CI environments structurally cannot catch — (a) the Dockerfile's base-image tag must be verified against the registry API, not assumed (CI builds the jar, never the image); (b) code paths that only execute when a REAL secret is present (the LLM chain with a live key) are invisible to zero-key CI boots — the with-key path needs its own rehearsal or a canary; (c) a JVM on a 512 MB cgroup with unbounded metaspace/code-cache stalls silently under GC thrash (no crash line, no log output, process alive) — the signature is "logs stop mid-Hibernate → port-scan timeout" and the fix is the small-container recipe (cap every region, SerialGC, C1-only JIT, ExitOnOutOfMemoryError so future walls fail visibly).
