## Context

T-C57 unified the hub's review queue over the derived feed ∪ the device trail with newest-evidence-wins **per card**, and deliberately did not cross-merge trails: core served derived schedules, not raw events, and merging two DERIVED schedules would invent history. A learner who rated the same card on two devices therefore got one side's history, not both — the derivation input was whichever side's newest record won.

Serving the RAW append-only V47 trail makes a true chronological merge honest: both sides become event streams, and a per-card merge of two event streams "is exactly the events that exist, each represented once" — it invents nothing. The Ebbinghaus derivation stays bit-for-bit the frozen ladder (ADR-031 computed-at-read); only the derivation INPUT changes, from "one side's trail" to "the union of both sides' events".

**Dedup is the load-bearing design point.** V47 stamps `occurred_at` SERVER-side (`FlashcardRatingController` uses `Instant.now()`; the hub POST carries no timestamp), so the same physical flip has a device-clock timestamp in localStorage and a server-clock timestamp in core — `(cardId, rating, occurredAt)` cannot dedup across sides, and a heuristic time-window would corrupt legitimate fast re-rates. Duplicates are not cosmetic: the ladder's interval is driven by the trailing KNOW streak, so a double-counted "know" inflates the streak and pushes a card's due date OUT — under-practice, the harmful direction.

The honest fix is receipts at the only moment the truth is knowable: the bridge already learns the sync outcome per flip (`submitFlashcardRating` resolves synced / local-only) — it just never persisted it.

## Accepted

- **Core serves the raw trail, bounded.** `GET /api/v1/learners/me/flashcard-rating-trail`: the learner's own V47 rows newest-first in keyset pages ordered `(occurred_at DESC, id DESC)` — gap-free and duplicate-free across pages INCLUDING `occurred_at` ties (opaque `TrailCursor` codec, fail-closed: malformed cursor → 400, never guessed); `limit` clamped server-side (200/page walk, 25-page safety cap — a deck count per learner per V47's scale note, not a firehose); nodes resolve to anchor codes with honest nulls (display degrades, the row does not); auth required. The endpoint is a pure read: nothing persisted (ADR-031 doctrine extends trivially).
- **The device trail records sync receipts.** Each localStorage trail entry gains an additive optional `sync: "core" | "local"` (no schema break: absent = recorded before this lane), written by the bridge from the submit outcome it already receives. `rateFlashcard` returns the event `at`; `markFlashcardTrailSync` flips the receipt.
- **Merge rule per card (the true merge):** account events + device entries marked `"local"` + device unmarked entries ONLY when the account has no events for that card. Historical unmarked entries might BE the account's copy (recorded before receipts existed) — keeping them errs due-EARLIER (over-practice), the conservative direction; a synced device entry is dropped (core is append-only: a 2xx POST means the row exists and nothing deletes it).
- **No heuristic timestamp-window dedup, ever** — a same-rating-nearby-time heuristic would corrupt legitimate fast re-rates; receipts, not timestamps, are the cross-side identity.
- **Degradation rungs preserved verbatim:** the T-C57 feed union rung and the device-only rung remain, chosen whenever the trail walk cannot complete; the drawer footnote states the true coverage for every rung.
- **Honesty pins untouched:** ratings drive review TIMING only — never mastery (no BKT update, no SkillState row, `FlashcardRatingTrailFlowIT` re-pins the edition with SkillState empty); no bridge-gate widening (the pilot-course + signed-in gate is mirrored exactly on the read side; the 44-pack widening stays a separate recorded next_safe_action).

## Consequences

- A card rated on device A (synced) and offline on device B (marked local) now shows the TRUE merged history: the offline event enters the derivation, the synced event is not double-counted, the streak cannot inflate. A card whose only events are unmarked historical device entries and whose account trail is empty derives exactly as T-C57 did.
- The merged trail is capped deterministically: `TRAIL_CAP` parity with the frozen ladder (a trail longer than the cap derives the capped interval — 12 knows → 32d maintenance — same as the full trail), malformed ISO instants never enter the merge, and the chronological interleave is per-card true.
- **UNVERIFIED until a live probe:** the field semantics of receipts on real devices (two browsers, one signed-in account) — recorded UNVERIFIED in T-C61.yaml; the pin suite covers the logic, not the devices.
