# Archify Integration\n\n**Status:** ACCEPTED as developer/agent tooling candidate  \n**Runtime status:** NOT A PRODUCTION RUNTIME DEPENDENCY  \n**Canonical source of truth:** GitHub repository artifacts and implementation evidence\n\n## Purpose\n\n[Archify](https://github.com/tt-a1i/archify) is adopted as an optional developer/agent capability for creating source-backed, interactive architecture, workflow, sequence, data-flow, and lifecycle diagrams.\n\nIt is intended to improve:\n- architecture review;\n- multi-agent coordination;\n- onboarding;\n- repository/source visualization;\n- research communication;\n- experiment/demo documentation.\n\n## Installation\n\nFor an agent environment that supports the Skills CLI:\n\n    npx skills add tt-a1i/archify -g\n\nInstallation is environment-specific and is not part of the SyllabAI application runtime.\n\n## SyllabAI usage rule\n\nGenerated Archify HTML is a **derived visualization**, not canonical architecture.\n\nWhen a diagram represents existing implementation:\n1. Prefer repository evidence over memory.\n2. Pin source-backed claims to a concrete commit/ref where practical.\n3. Cite relevant repository files/line ranges in the diagram when the Archify source-evidence mode supports it.\n4. Preserve SyllabAI status labels where architecture claims are not verified.\n5. Do not use a diagram to silently promote `PROPOSED`, `INFERRED`, `REPORTED`, or `UNVERIFIED` material to `IMPLEMENTED` or `VERIFIED`.\n\nWhen a diagram represents target architecture, label it explicitly as `PROPOSED` or `ACCEPTED` according to the canonical project artifact.\n\n## Recommended first diagrams\n\n1. SyllabAI system architecture across `syllabai-web`, `syllabai-core`, resources, retrieval, KG, learner model, and Tutor.\n2. Retrieval pipeline from learner query through evidence sufficiency and claim/citation validation.\n3. Learner evidence lifecycle from raw conversation to governed learner state.\n4. Smart Mark → evidence → remediation → practice workflow.\n5. Local Intelligence Layer: deterministic UI → optional local controller → semantic tools → governed backend → Tutor/NBA.\n6. `syllabai-demo` experimental architecture and its provider abstraction.\n\n## Boundary\n\nDo **not** add Archify as a Java, Next.js, browser, or production deployment dependency merely to render diagrams.\n\nThe preferred architecture is:\n\n    GitHub source / canonical artifact\n                  ↓\n           Archify agent skill\n                  ↓\n          validated JSON IR\n                  ↓\n         self-contained HTML\n                  ↓\n        review / docs / demo surface\n\n## Verification required before wider adoption\n\n- Agent environment can install and invoke Archify reproducibly.\n- Generated diagrams validate successfully.\n- Source-backed diagrams point to real repository evidence.\n- Generated output remains usable without a hosted Archify service.\n- Archify does not become a hidden runtime dependency.\n
